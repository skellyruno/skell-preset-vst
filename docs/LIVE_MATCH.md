# Skell Match — first native pass

- One-click live-stage overlay; local dry main bus analysis before MIC, input trim and rack. Existing sound stays unchanged while listening. Minimum six seconds elapsed audio and four seconds active RMS windows; up to twenty seconds of input, plus 45-second GUI timeout. Reject excessive clipping and insufficient data. No file persistence, network, audio callback allocation, or audio-thread UI work. Temporary PCM (at most 20 seconds stereo, 30.72 MB at 192 kHz) is allocated lazily on the message thread; capture storage is reused until processor destruction. Worker copies are released when closing/retrying.
- The first recipe uses actual low/high band-energy proxies, RMS, peak and crest to build a bounded native EQ, compressor and optional de-esser. It is a heuristic starter, not a complete optimized voice-specific recreation, neural VAD or stem separator. Reference files influence spectral/crest targets; similar profiles rejected. No exact match claim. No full-song support yet.
- Dry/reference WAV/AIFF/FLAC files decoded on a worker, capped at 128 MiB and 20 seconds analyzed. A single owned worker pool publishes only profile results; cancellation and destruction invalidate jobs and join the decoder, preventing late application. Audio statistics publish at 20 ms windows rather than every host block. Dry PCM is retained in memory during the Match session; reference files retain statistics only. Listen returns to the real rack for DAW playback, not an embedded audio player. Undo restores the previous native rack. Hosted VST3 racks cannot be safely snapshotted and are not replaced.
- Follow-up: independently measured real vocal A/B, existing Sound Match solver integration, calibrated multiband FFT/voice activity, source/reference alignment, gain-matched audition, stem separation, explicit user approval for major rack topology changes, local Quick4 listening/done capture. Preserve old parameter/program identities.

Local native renderer `--extras` exercises actual Match controls, dry callback, silence rejection, applying the generated rack, and undo/redo, with real editor PNGs. These test stimuli are synthetic, not listening-test recordings.

The performer microphone is also a real Match button. Its accessible hit target follows the same microphone rotation and body lean as the visible artwork. The separate rack MIC control retains microphone modeling. The extras renderer uses the actual stage microphone target for the listening scene; other Match tests retain the header trigger.

## Measured search

25 native-kernel renders (starter plus two coordinate passes), bounded six continuous controls. Fixed disjoint halves of the dry sample supply audible 1.5 s phrases (extended to 2.5 s for sparse input). The training metric combines relative low/high spectral energy, crest and RMS deviation in dB plus headroom penalties. The final training winner is evaluated on the held-out phrase; if it regresses against the starter, fall back to the measured starter only if it improves on dry in both phrases. Otherwise leave the rack untouched. This is not a full processBlock render: scorer shares native EQ/compressor/gate/de-esser kernels and parameter mapping, with settled mixer state. No perceptual similarity percentage, pitch matching, reverb/delay identification, or full solver claim. The reference target is a bounded summary, not aligned waveform matching. Cancellation stays on the owned worker. Next gate: compare exact host render to the scorer on real vocals, add multiband metrics and broader effect candidates.

Real local fixture check (44.1 kHz, private sources not committed): Hop Out dry held-out weighted feature error 1.579 -> 0.856; Speakerz 2.175 -> 1.477 (measured starter retained because further training improvement did not generalize). These are relative feature errors, not exact reference similarity or listening judgments.
